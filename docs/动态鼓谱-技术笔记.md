# 动态架子鼓鼓谱 — 技术笔记

> 本文件是「制作动态鼓谱」的学习笔记：记录目标形态、已验证的参考机制、可选技术路线、
> HyperFrames 约束与本地工具链现状。后续提问可直接引用本文件结论。

## 1. 目标产物（从参考视频反推）

参考来源：B 站 UP 主「罗曼音乐_Roman_Music」的动态鼓谱视频（已下载 3 个 BV：
`BV1ZXsazYEsF`、`BV1MisVzYERQ`、`BV1hDkvBWEG7`，抽帧在 `refs/frames/`）。

画面结构（以《麒麟》为例）：

1. 顶部固定标题区：曲名（大字）+ 右侧 UP 主名 / 制谱人。
2. 速度标记（如 `♩=71`）+ 拍号 `4/4` + 打击乐谱号（两条竖线）。
3. 谱面为 **5 行系统（system）** 左右的固定版式，含小节号、反复记号、连音数字（如 `6`）。
4. **页面本身不滚动**，而是在当前小节上有一根半透明的浅蓝色竖直「播放光标」由左向右扫过。
5. 光标经过时，**被演奏的音符变蓝**（高亮），并伴随一个小绿色标记。
6. 一行扫完后，光标跳到下一行的行首继续扫；非当前行的谱面整体更淡/更灰。

**结论（回答 `refs/probe8.ps1` 的疑问）：是「固定版式内光标扫行后跳转」，不是连续横滚。**
这对实现方式影响很大 —— 不需要做连续滚动计算，只需要按小节/拍算出光标的 X 坐标即可。

谱面排版风格与 MuseScore 默认输出高度一致（打击乐谱号、x 形 hi-hat 符头、
符尾横梁、附点、休止符、连音数字），基本可以认定参考视频是用 MuseScore 出谱后再叠加动效。

## 2. 三条可选技术路线

| 路线 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. MuseScore 离屏渲染成图 | `MuseScore4.exe -o out.svg/png` 出整页图，HyperFrames 里做光标与高亮叠加 | 排版最正统、与参考视频一致；成本最低 | 图片是死图，无法直接知道每个音符的坐标；高亮只能靠额外测量或半透明遮罩 |
| B. webmscore（MuseScore 的 WASM 版） | 在 Node/浏览器里把 `.mscz` 直接渲染成 SVG，元素带 id，可在 HyperFrames 内逐音符控制 | 排版正统 **且** 可编程控制每个 SVG 元素；确定性好 | 需要装 npm 包、确认导出 API；体积较大 |
| C. VexFlow 浏览器内从头绘制 | 用自己的数据模型（类似 `score/groove.json`）直接画谱 | 完全掌控每个音符坐标与高亮；可做任意动效 | 需要自己实现鼓谱排版规则（符头样式、符杠、连音、小节换行） |

**当前倾向**：先用 A 验证「版式 + 光标扫行」的观感，若要精细高亮再切 B；
若后续要做「任意曲目自动生成」（数据驱动、无人工排版），则 C 更合适。

## 3. HyperFrames 关键约束（来自 `/hyperframes` 与 `/hyperframes-core` 技能）

- 一个合成（composition）= 一个 HTML 文件，用 `data-start` / `data-duration` 声明时间。
- 每个合成注册**恰好一个**暂停的根时间轴，键名必须等于根节点的 `data-composition-id`：

```js
// 注册唯一根时间轴；键名必须与根节点 data-composition-id 完全一致
window.__timelines["main"] = gsap.timeline({ paused: true });
```

- 禁止任何不确定性：`Date.now()`、`Math.random()`、网络请求、输入状态。

```js
// 反例：渲染时时钟会导致同一帧多次渲染结果不同，破坏可 seek 性
const t = Date.now(); // 禁止
```

```js
// 正例：所有时间点来自谱面数据（拍号 + BPM），渲染可重复
const tSec = (bar - 1) * beatsPerBar * (60 / bpm) + beat * (60 / bpm);
```

- 不要对 `class="clip"` 的元素 tween `display` / `visibility` / `autoAlpha`，要动就动子节点。
- 不要用 CSS `transform` 设置初值再让 GSAP 动同一个属性（lint 报 `gsap_css_transform_conflict`）。
- 改完必须跑 `npm run check`（= `npx hyperframes check`），它一把过 lint + 运行时 + 版式 + 动作 + 对比度。
- 项目 CLI 固定在 `hyperframes@0.8.156`；升级前先跑
  `npx hyperframes@latest upgrade --project . --check`（只读探测）。
- 本机已确认可用：`npx hyperframes docs data-attributes`（离线文档）、
  `npx hyperframes catalog --query "..." --json`（素材库检索）。
  注意：以「music notation / sheet music」为关键词检索官方 registry **返回空**，
  说明**没有现成的「乐谱」素材块，谱面必须自己造**。
- 本工程 `hyperframes.json` 里 `authoringSkill` 是 `music-to-video`，
  即官方推荐用「音乐驱动」那条工作流组织视频结构。

### MuseScore 命令行（Windows 形如 `MuseScore4.exe [options] [file]`）

```bash
# 按扩展名导出：.pdf / .png / .svg / .musicxml / .mid / .mp3 均支持
MuseScore4.exe -o 'out.svg' 'in.mscz'

# 导出成图时提高分辨率并裁掉四周空白（做视频素材常用）
MuseScore4.exe -r 300 -T 10 -o 'page.png' 'in.mscz'

# 走批量任务 JSON，可一次产出多种格式，甚至挂插件
MuseScore4.exe -j job.json
```

批量任务 JSON 形如：

```json
// 一个任务里同时产出 PDF / MusicXML / MIDI，并可指定 QML 插件
[
  { "in": "score.mscz", "out": ["score.pdf", "score.musicxml", "score.mid"] }
]
```

其它有用的开关：`-p/--plugin <name>` 导出时执行 QML 插件（例如给音符上色）、
`-P/--export-score-parts` 导出分谱、`--score-media` / `--score-meta` 导出结构化信息、
`-r/--image-resolution` PNG 分辨率、`-T/--trim-image` 裁边距。

### webmscore（路线 B 的关键）

```js
// 在 Node 里加载 .mscz，之后可导出 SVG/PNG/PDF/MIDI/音频

WebMscore.ready.then(async () => {
  const score = await WebMscore.load('mscz', msczdata)

```

## 5. 记谱知识要点

### 鼓谱的视觉规则（参考视频里出现的）

- 打击乐谱号：两条竖线（不是高音/低音谱号）。
- 符头形状承载乐器语义：hi-hat / crash 用 **x 形符头**，军鼓用普通实心符头，
  底鼓在下加线附近，开镲常带 `o` 标记。
- 十六分音符以 **四条符杠** 连成组，是鼓谱信息密度最高的部分。
- 连音组数字（如 `6`）标在符杠上方。

### VexFlow 里怎么表达（路线 C）

```js
// 用 key 的修饰后缀控制符头形状：x2 = x 形（镲片），无后缀 = 普通实心（军鼓/底鼓）
const hh = new Vex.Flow.StaveNote({ keys: ['g/5/x2'], duration: '16' })  // hi-hat
const sn = new Vex.Flow.StaveNote({ keys: ['c/5'], duration: '16' })     // snare
```

```js
// 打击乐谱号 + 单音符上色（做「命中变蓝」高亮）
stave.addClef('percussion')
note.setKeyStyle(0, { fillStyle: '#2f6fd0', strokeStyle: '#2f6fd0' })
```

```js
// 拿到音符的绝对 X 坐标，用来算播放光标位置
const x = note.getAbsoluteX()
```

多声部（hi-hat 一路、军鼓/底鼓一路）用 `Voice` + `Formatter.joinVoices().format()` 合并格式化。

### 7.8 播放光标与排版修正（2026-10-14 第二轮）

- **时间轴定律**：谱面第 1 小节 **不是** 歌曲 0 秒，而是鼓组进入点 **14.33 秒**（实测底鼓首次进入，
  与用户给出的「14–15 秒」一致）。谱面 1–60 小节 + 61–79 小节重复编排，整曲 191.85 秒。
  音频分频段检测在引子段会被吉他/人声污染，**对齐以谱面与用户口径为准**。
- **坐标空间陷阱**：`MuseScore4.exe -o` 导出的 SVG 内部坐标是页面原始尺寸（如 9924×14028），
  而脚本里用的 PNG 被缩放到 3000 宽；混用两者会导致画面滚动错行、光标跑偏。
  解析 SVG 后必须按 `viewBox` 宽度换算到 PNG 空间（`tools/render_video4.py` 已内置）。
- **光标做法（定型）**：每行 4 小节；小节内以「小节左端 → 各音符列 → 小节线」为锚点，
  按十六分位置线性插值。这样光标连续行进、不跳空白，且在每个鼓点上正好压住音符列。
- **成片**：`refs/out/绿光鼓谱_最终版.mp4`（1920x1080 / 60fps / 3:11.85 / AAC 192k）。
- **仍待精修**：引子（1–7 小节）与各过门（13–16、28、36–38、54–56、60）为「按 PDF 读出的近似」，
  主织体（16 分踩镲 + 2/4 拍边击 + 1/3 拍底鼓）与谱面一致；若要逐音完全一致，需按 17 行谱逐行精读重建。
